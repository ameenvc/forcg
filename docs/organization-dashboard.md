# Organization dashboard

`/user/dashboard` is an authenticated, organization-wide aggregate snapshot. It replaces the prior dashboard and its hundreds of unconditional queries. The controller retains auth/MFA and session type handling. It reads `modenadisable` for this installation/database and includes only enabled entries from the 24-module registry in `config/my_board.php`. Enabled modules lacking a supported feed still receive a directory shortcut; future modules require an explicit registry mapping. Occupational-health records and individual activity/medical details are never loaded.

`OrganizationDashboardService` loads selected workflow feeds from that registry, deduplicated by source table. It excludes soft-deleted/is_deleted rows and cancelled/archived/deleted stages. One aggregate query groups by status and supported deadline fields for each connected table; it never fetches individual titles, assignees or record details. MySQL column metadata is loaded once per snapshot. Query count is independent of record count. No N+1 per employee, department or record queries remain. There is no background polling or invented historical trend; refresh the page for a fresh snapshot. Responses are private/no-store.

Open/active means a nonblank, nonterminal status in a connected source. This includes continuous registers and is not a personal task count. Closed/completed follows the source's explicit completion states. Review/approval detects those terms in the mapped stage; additional workflow views of a shared table are not counted again. Missing stages/tables are unavailable; modules can be partial. Empty connected tables are genuine zeros; an entirely unconnected dashboard displays dashes rather than a false all-clear.

Overdue means an open record with the first strictly parsed source deadline before today. Due soon includes today through day seven inclusive. Supported date formats are ISO dates/timestamps and explicit day-first slash/dash dates. Invalid, blank or composite dates are not guessed and are shown as open-without-usable-deadline in coverage. Historical records are not silently removed. This does not cover every role-specific deadline or imply everything else is complete. Coverage details name every connected/unavailable source.

Priority modules are ordered by overdue counts then decision-stage counts. Legal Not Complied records raise a separate compliance flag; deleted records are excluded. No organization performance score is inferred by averaging heterogeneous module completion counts. ESG performance and personal My Board remain separate entry points. Existing destination permissions still apply, and module configuration is navigation scope, not a replacement for endpoint authorization.

Scoped CSS uses the shared font, blue/purple branding and global `data-risk-theme` light/dark toggle. Module cards support local search and area filtering without additional requests. No chart library, remote CDN or new package is required. Versioned CSS/JS paths do not call filemtime. Deploy controller, service, view and assets together; no database migration is needed. Clear compiled views if a deployment serves the prior page.

Tests cover disabled-module query exclusion, soft-deletion and cancellation, known/invalid deadlines, unknown stages, duplicate workflow sources, all-module coverage, aggregate query counts, compliance flags, authentication and escaped rendering.

## Management-first overview

The default view is now **Management overview**. **All modules** is a secondary tab; without JavaScript both sections remain accessible through anchors. Tabs support keyboard arrows/Home/End, direct `#od-modules` links and ARIA tab/panel relationships. Management-area shortcuts open the directory with its area filter applied.

The first indicators show open High enterprise risks and legal non-compliance when those modules are enabled, then overdue and review/approval records. If risk/compliance are disabled, connected-module and upcoming-deadline indicators replace them. Risk exposure counts only nonterminal, nonblank risk stages, excludes deleted/cancelled rows and includes an Unassessed category. Legal evaluation distributions retain Other/unevaluated records in the denominator; legal exceptions derive from the same filtered groups. Charts are current snapshots, not historical trends.

Action closure graphs use only connected mitigation, corrective, audit-finding, HSE and near-miss workflows. They show exact closed/total counts rather than averaging continuous registers into a misleading organization score. Closure does not prove timeliness or effectiveness. Safety workflows appear when enabled. The ESG card separately summarizes accepted/pending source records and accepted records with assurance reports recorded; it never claims provider verification. Missing evidence storage remains visibly unconnected. Management-area summaries state when no summaries are connected instead of asserting zero issues. The complete module cards and detailed coverage remain in All modules.
