# Organization ESG readiness — model 1.0

The authenticated `/user/score` replaces the legacy volume-based score and hard-coded global benchmark. It reads this organization's installation database, observes module-enable flags, and exposes aggregates only. It measures organizational improvement rather than procurement qualification. The scorecard itself requires no migration; evidence storage requires the migration below.

`config/esg_score.php` is the reviewed, versioned rule registry. Pillar weights E/S/G are 35/35/30. Indicator weights sum to 100 per pillar. Each connected indicator measures satisfactory workflow statuses divided by all non-cancelled, non-archived, non-deleted records. Blank status earns zero; missing schema and empty tables have no observed score. Missing or disabled indicators retain their headline denominator and earn no points; they are never treated as proof of good performance. Headline readiness = sum(pillar weight × indicator weight × observed score / 10000). No evidence at all yields no score, not zero performance or perfect performance. Pillar observed results renormalize only connected weights and must always be read with coverage.

This measures internal workflow readiness, not emissions, social impact, control effectiveness, assurance, certification, an ISO conformity statement or externally verified outcomes. Scope is all current stored eligible records; there is no claim of annual comparability, prior-month trend or historical snapshot retention. Deleting/archiving records can change denominators; a tamper-resistant evidence ledger is not provided. Incident counts themselves never earn or lose points. Workflow completion proxies are not outcome measures.

GHG inventory, resource consumption, labour rights and anti-bribery/supply-chain evidence remain explicit unconnected requirements. All 24 module names are shown in coverage; modules lacking validated mapping are supplementary rather than silently rewarded. Organizational/industry materiality, verified reporting periods, evidence expiry, independent assurance and approval histories require organization policy and additional structured measurement sources. They cannot be inferred from this score. Do not use observed-only pillar scores as externally assured outcome measures.

Any stored legal `Not Complied` record raises a compliance review flag. Otherwise the assessment remains internal and requires evidence review, regardless of score. CSV and print/PDF expose model version, coverage, snapshot time and internal status. Exports remain authenticated and private/no-store. No externally certified status is inferred.

Deploy controller, service, registry, Blade and CSS together. Versioned asset URL avoids filesystem timestamp failures. Existing auth/MFA on UserController applies. Clear Blade cache if the deployment serves the former view. Schema mismatches are shown as unavailable and logged without source contents. Tests cover weighted denominators, blank/missing/disabled sources, deletion/cancellation, blockers, all-module coverage and view claims.

## Evidence & emissions register

The page is now organization-focused (`Organization ESG performance`); legal non-compliance raises an ESG review flag, not a procurement qualification decision. `/user/score/evidence` adds immutable source submissions, private attachments, CSV imports and append-only application review events. It requires the additive migration:

```
php artisan migrate --path=database/migrations/2026_11_06_210000_create_esg_evidence_tables.php --force
php artisan view:clear
```

Only run this specific migration for this feature, rather than all legacy migrations. Development wrapper: `bash tools/risk-ai-dev.sh migrate-esg`. Before setup, the register explains setup is needed and does not crash the scorecard.

All authenticated organization users may submit and read records. Admin/superadmin accounts or users with `manage-esg-evidence` in `user_gates` may review. A submitter account cannot review its own record. This is account separation, not proof two accounts represent different natural persons. There is no UI granting review privileges. Existing auth/MFA and CSRF apply. Supported source uploads are PDF/JPEG/PNG up to 10 MB; files use the explicit private local disk and authenticated download, SHA-256 source fingerprint and private/no-store responses. CSV imports are capped at 100 rows / 1 MB and transactional. Duplicate normalized source identities roll the entire import back. Rejected sources require a new revision reference/title to resubmit; historical source/review rows remain intact. This audit history is application-level, not an independently immutable ledger.

Emissions store activity quantity, unit, kgCO2e-per-unit factor and factor publication. `tCO2e = quantity * factor / 1000`. No factors are assumed or fetched; reviewers must confirm factor/unit compatibility, geography, year, boundaries and source authenticity. Zero activity/factors are allowed with source evidence. Scope 2 requires location or market basis; Scope 1/3 use direct. Scope 3 categories must be named in activity/reference. Accepted subtotals are grouped by exact site, start/end period, scope and basis; no cross-period/global total is presented. Scope 2 alternatives must not be added. Duplicate identity protection does not detect overlapping/renamed activities, so reviewer reconciliation is still essential. It is not a complete GHG Protocol inventory or certified footprint.

Provider ratings retain original provider, grade and scale. Internally accepted evidence is not labelled independently verified. Optional external assurance requires a provider name, reference and PDF attached by an authorized different reviewer. The UI explicitly says `External assurance recorded`, not API-verified. No live provider API is connected, no authenticity is inferred, and evidence/ratings do not automatically change workflow readiness scores. Provider API integration still requires supported API documentation, licensed access and server-side credentials. No public links, outbound API calls or customer publishing are implemented.

Submitters or authorized reviewers can withdraw a record with a mandatory reason. Its source, previous review and events remain readable; accepted inventory totals exclude it immediately. Neither delete nor overwrite endpoints exist. The source form progressively shows the applicable emissions/rating fields, calculates an estimate in-browser, and revalidates all required fields server-side. Database values and source strings are always rendered as escaped text.
